# How the code works, and how it was tested

The repo files are `1.md` (guide), `2.txt` (packages: `scrapling[fetchers]==0.5`, `openpyxl>=3.1`), `3.py` (setup), `4.py` (watcher), `5.py` (API finder), `6.py` (batch text collector), `8.py` (chosen-text collector), and `9.py` + `10.yml` (the automatic queue on GitHub; see the last section). `7/` is these notes. `4.py`–`6.py` write to a local `data/` folder, which must not be committed because it holds cookies. `8.py` writes only to the private folder `~/scrap-private`.

## `3.py`: setup

Checks for Python 3.10 or newer and installs `2.txt`. If a Homebrew or system Python refuses the install, it retries as a per-user install. It then runs `python -m patchright install chromium` and checks whether Google Chrome is installed. Scrapling 0.5 drives the browser through **Patchright**, which expects its own Chromium build. `playwright install` alone left the wrong build, which is why it uses Patchright's installer.

## `4.py`: one-page watcher

- **One stealth browser session** (`StealthySession`, real Chrome, `solve_cloudflare`, canvas noise, WebRTC blocking, 60 s timeout) stays open. One window with one working tab reloads the page every ~90 s, randomly 70–110 s. A blank second tab is normal. Stopping it closes everything.
- **Which page:** either `URL`, or `LINKS_FILE` plus `LINK_ROW`. It reads the .xlsx with openpyxl and takes the **black-filled** cell in that row (from an RGB colour, theme colour "Text 1", or indexed black), or else the row's only link. It reads hyperlinks, plain URLs and `=HYPERLINK()` formulas.
- **Privacy (`HIDE_ADDRESS`):** every printed line, Scrapling's own log lines (through a logging filter), error tracebacks, and `4-checks.csv` / `4-blocks.csv` replace the page address with "[your page]", other links on that site with "[a link on the site]", and the site's name, even inside page titles, with "[the site]".
- **What it reports:** with `ITEM_SELECTOR`, each new listing (text, link, `PRICE_SELECTOR`); otherwise "page changed" based on a hash of the page text. A seen-list stops repeat alerts after a restart.
- **Recognising blocks:** 429 or Cloudflare 1015 means rate limit. 1005–1008 means IP ban. 1010 means fingerprint ban. 1020 or "Sorry, you have been blocked" means firewall. A "Just a moment" title or the `cf-mitigated: challenge` header means challenge. A 403 means firewall, and a 5xx means site error. A page that loads but has no listings and far fewer links than usual counts as a quiet block. A lost connection is not a block.
- **Fixes, one per blocked check, with the wait doubling up to 30 min:**
  - rate limit: wait out `Retry-After`, then check 1.5× slower;
  - challenge: wait → visible Chrome → fresh session → slow down;
  - fingerprint: fresh session → visible Chrome → switch browser;
  - firewall and quiet block: fresh session → visible Chrome → slow down;
  - IP ban: nothing to try, go straight to sleep.
- **Out of fixes:** it sleeps 3 h, then makes one test check, then 6, 12 and 24 h. It never quits on its own. Once a test passes, it resumes 1.5× slower.
- **Learning** (`data/4-learned.json`, per site):
  - After 6 h without a block it tries checking 10% faster. If that gets blocked within 2 h, it goes back and records a floor it won't go below.
  - It remembers a browser setting that fixed a block.
  - After a mild redesign it re-finds the listings with Scrapling's adaptive matching and saves the new selector.
  - Any setting the owner changes at the top of the file replaces what was learned for that setting.
- It never edits its own code or upgrades Scrapling. Once a day it notes whether a newer Scrapling exists.

## `5.py`: API finder

Opens the page once with `record_requests=True`, scrolls, and lists the background XHR and fetch calls, JSON and largest first, saving them to `data/5-api-calls.json`. **It prints real addresses and has no privacy mode yet.**

## `6.py`: batch text collector (for the ~130,000 links)

- **Reading the list:** every row of the spreadsheet from `FIRST_ROW` to `LAST_ROW`, taking the black-filled link in each row, or else the row's first link.
- **Workers:** `BROWSERS` workers, default 2. Each runs one `AsyncStealthySession` on its own Decodo port, so its own sticky IP.
- **How each lookup works:**
  1. If this IP already passed the site, it fetches the page as **plain text** with Scrapling's `FetcherSession` (curl_cffi). It goes through the same proxy port, with the browser's cookies for that site (including `cf_clearance`), the browser's exact user agent and Accept-Language, and the TLS impersonation profile closest to that Chrome version.
  2. Otherwise, or if plain text gets challenged, it uses the browser. On the first visit it loads everything, so the Cloudflare check can run. Once the IP has passed the site it skips images, fonts and CSS.
  3. If a challenge stays up, it waits 4–8 s and takes a second look on the same IP.
  4. If it's still blocked, it moves that worker to another port (another IP), at most twice per row. A blocked port rests for 10 minutes. If all ports are resting, it waits.
  5. If plain text gets refused 3 times on a site where it never once worked, that site goes **browser-only** for the rest of the run.
- **Safety brakes:** 10 blocked lookups in a row across all workers pauses everything for 15 minutes. `LIMIT` caps the number of lookups per run; the default is 50, sized for the 100 MB trial.
- **Saving:** results go to SQLite (`data/6-text.db`) after every row and are exported to `data/6-text.csv` every 25 rows and at the end. The CSV has row, status, how (text or browser), chars, title, text cut at 32,000 characters for Excel, tries and time. On restart it skips rows that are `ok` or `not_found`, or that have failed 3 times.
- **Privacy:** it prints only row numbers. Any URL in a message, including Scrapling's log lines and tracebacks, becomes "[link]", and the password becomes "[password]". It reads the password from `PROXY_PASSWORD_FILE` (default `~/decodo-password.txt`).
- **Stopping:** Ctrl+C or the stop button closes every browser, saves the CSV and prints "Stopped. Run it again to carry on…".

## `8.py`: chosen-text collector (the main tool now)

- **The private folder** (`PRIVATE_FOLDER`, default `~/scrap-private`) holds everything private:
  - `links.csv`, written by the owner;
  - `samples/row-N.html` and `.txt`, plus `HOW-TO-fields.md`, written by the sample run;
  - `fields.json`, written by the second chat;
  - `results.csv` and `8-results.db`, written by the full run.

  Nothing private is written anywhere else.
- **Reading `links.csv`:** it detects the delimiter. `LINK_COLUMN = 0` takes the first web address in each row; a number or a heading picks a column. Row numbers are file line numbers. Duplicate links are skipped, and finished links are tracked by a hash of the link, so rows added later don't shift anything. If most rows have no address, it warns that the export probably kept only link text.
- **Sample run** (when there's no `fields.json`): it opens the first `SAMPLE_PAGES` (20) links in the browser, so JavaScript-drawn content is included. It saves each page's HTML and text and writes `HOW-TO-fields.md`, which explains the `fields.json` format to the second chat.
- **`fields.json`:** `{"fields": {"name": "css selector", ...}}`. A plain string is CSS, or XPath if it starts with `/`. `::text` and `::attr()` work. An object form takes `css` or `xpath`, plus optional `all` (join every match with " | ") and `regex` (keep a pattern, or its first group). Each value is cut at 32,000 characters.
- **Full run:** the same engine as `6.py` (sticky ports, browser pass, plain text, moving off blocked ports, safety brakes), plus:
  - **Missing items on a plain page:** the page is reopened in the browser. If the browser finds more, that counts toward "needs JavaScript", and after 3 the site goes browser-only. If the browser finds the same, that counts toward "plain is enough", and after 3 it stops double-checking.
  - **Time zones:** each new browser first looks up its port's location (`IP_CHECK_URL`, `https://ip.decodo.com/json`) and sets `timezone_id` to match, falling back to the Mac's time zone.
  - **New links:** `WATCH_MINUTES > 0` keeps it running and re-reads `links.csv` that often, for links added later.
  - **Results:** written to SQLite after every link, exported to `results.csv` every 25 links and at the end. Columns: row, link, status, one column per field, found (e.g. `5 of 5`), how, tries, time. To redo finished links after changing `fields.json`, delete `8-results.db`.
- **Privacy:** it only prints row numbers and counts ("Row 412: ok - 5 of 5 items"). Links in any message become "[link]" and the password "[password]". It never prints field values or page text.

## Testing

All tests ran in a Linux cloud sandbox with no access to real websites. Local test servers stood in for the real thing.

**`4.py`, against a local fake shop:**
- It reported only new listings and kept the seen-list across a restart.
- Every block type got the right fix: the challenge went through the visible window, the rate limit waited out `Retry-After`, firewall and quiet blocks cleared with a fresh session.
- An IP ban led to sleep, then a passing test check, then resuming slower.
- A class-renamed redesign was followed.
- A speed-up that got blocked was rolled back and a floor recorded.
- No address leaked into the output or the shareable CSVs.
- Picking the black cell worked with theme-black fills, RGB-black fills and `=HYPERLINK()` cells, ignoring decoy links.

**`4.py`, on the owner's Mac against the real site:** worked for both rows tried. The first row-3 load took about 45 s.

**`6.py`, against a fake Cloudflare-style site through a fake proxy** (Basic auth, ports 10001–10003, with a password containing `@ : /`):
- Plain text with the browser's pass: 18 of 20 lookups came through as plain text.
- A blocked port: the worker moved to another IP and succeeded.
- A site that refuses plain requests: it switched that site to browser-only, and every row still succeeded.
- Stopping mid-run, resuming, and "nothing left to do" all worked.
- The CSV came out correct, and every browser closed on stop.
- No address, username or password appeared in the output.

**`8.py`, against a fake Cloudflare-style site through the fake proxy:**
- **Sample run:** 5 pages saved, including a price drawn by JavaScript. A row with no link was skipped.
- **Time zones:** each browser's clock matched its port (the site saw America/Chicago on port 10001 and America/Denver on 10002).
- **JavaScript-only item:** with 5 fields including the JavaScript-drawn price, it noticed the price was missing from plain pages, switched the site to the browser after 3 checks, and filled 100% of items.
- **Plain text when possible:** with fields that appear in plain HTML, 21 of 23 lookups came as plain text.
- **New links:** links added to `links.csv` were picked up on the next run, and only those ran.
- **Results and privacy:** `results.csv` had the right columns and values, and no link, value, username or password appeared in the output.

**Not tested yet:** `6.py` and `8.py` against the real Decodo proxy and the real Cloudflare site. Whether plain text gets past that site's Cloudflare is the big open question; the code falls back to the browser if it doesn't.

## Scrapling 0.5 details worth knowing

- **Browser sessions** (`StealthySession` / `AsyncStealthySession`) keep a pool of tabs (`max_pages`, default 1) and reuse them. `session.context` is the Playwright context, so `await context.cookies()` gives the cookies.
- **Proxies in browser sessions** are one fixed proxy per session. Using `proxy_rotator` opens a temporary context per proxy, which loses cookies, so `6.py` runs one session per port instead.
- **`record_requests=True` plus `session.network.search(...)`** replaced `capture_xhr` in 0.5.
- **The HTTP session** is `FetcherSession(...)`, used with `with` or `async with`. Per request it takes `cookies=`, `headers=`, `proxy=` and `impersonate=`. `stealthy_headers=False` keeps your own User-Agent. `follow_redirects="safe"` (the default) refuses redirects to private IPs.
- **Scrapling's logger** is called "scrapling" and is created when the fetchers are imported. Set its level after importing them, or it resets to INFO.
- **Adaptive matching** (`css(..., auto_save=True)`, then `css(..., adaptive=True)`) relocates only the **first** element, at a 40% similarity threshold. `4.py` adds `find_similar()` to recover the whole list. Big redesigns fall below the threshold.
- **Patchright and Chromium:** Patchright 1.64 expects its own Chromium build, which `3.py` installs.

## The automatic GitHub queue (`9.py` + `10.yml`), added 31 Oct 2026

**Where things live.** The code is `9.py` in this repo, which is public, so the workflow can check it out without a token. The workflow `10.yml` is copied by the owner into `BrettS600/results-links` as `.github/workflows/10.yml`. Never open that repo; see `7/1.md`. The proxy password is the repo secret `DECODO_PASSWORD`.

**One run** (one at a time, concurrency group `link-queue`):

1. **Job "Queue 1: open pages"**
   - `9.py plan` reads the links file, `results.csv` and `fields.json`, then says whether there's anything to open. It uses the Python standard library only, so idle runs skip installing the browser.
   - `9.py open` runs under `xvfb-run` with headful real Chrome.
     - It first tests the proxy password against `IP_CHECK_URL`; a 407 stops the run before any link is tried.
     - Then it uses the same engine as `8.py`: a browser pass, then plain text on the same sticky IP, falling back to the browser for items drawn by JavaScript, moving off blocked ports, and pausing after 10 blocks in a row. After 3 pauses it stops the run.
   - Each opened page is saved to `pages/row-N.html`, and every try is logged to `pages/manifest.jsonl`. Both are uploaded as the artifact `pages-<run id>` (30 days).
   - Before `fields.json` exists, it opens the first `SAMPLE_PAGES` links in the browser into `pages/samples/` instead.
2. **Job "Queue 2: read pages"** (runs even if queue 1 failed)
   - It downloads this run's artifact and runs `9.py read`.
   - With no `fields.json`, it copies the samples into the repo's `samples/` folder, with `index.csv` and `HOW-TO-fields.md`.
   - Otherwise, it reads unread samples, then any earlier artifacts newer than the newest `run` in `results.csv` (bundles whose reading never finished, fetched with `gh run download`), then this run's.
   - It applies `fields.json` to each page, rewrites `results.csv`, refreshes `check/`, and commits as github-actions[bot]. It uses `pull --rebase` with retries, so the owner's pushes in the meantime don't clash.
   - It writes `more=true` when links are left and this run made progress. If `KEEP_GOING` is "true", the workflow then dispatches itself. `GITHUB_TOKEN` pushes don't start workflows, but `workflow_dispatch` does.
   - **Re-reading:** when a push adds or changes `fields.json`, or the reread box is ticked, it reads samples plus every artifact still kept, oldest first.

**Rules for `results.csv`:**
- There's one row per link, keyed by the link.
- A newer run's try replaces an older one, but a failed try never replaces an ok row.
- `tries` counts real attempts; re-reading a page doesn't count as one.
- A row is done when its status is `ok` or `not found`, or after `MAX_TRIES` (3) failures. The *retry failed* and *reopen missing* boxes override that.
- `found` is written `4 of 5`, not `4/5`, because Excel reads `4/5` as a date. `8.py` was fixed the same way.
- Before a write would pass `RESULTS_MAX_MB` (95), the file splits into `results-2.csv` and so on. Reading merges the parts back.

**Tested 31 Oct 2026, in the sandbox.** The stand-ins were:
- a fake Cloudflare-style site: a challenge cookie tied to the user agent, a price drawn by JavaScript, and a 404 row;
- a fake proxy on 3 ports with a password containing `@ : /`, where port 10003 always returns "Sorry, you have been blocked";
- a fake `gh` that stores artifacts;
- a bare git remote for the results repo, with a script that plays each job of `10.yml` in turn.

Results:
- **Samples:** 5 pages saved and committed, rendered with the JavaScript price. The browser clock matched each port's time zone. The blocked port was left for another, and the run carried on.
- **First `fields.json`:** the samples were read without reopening them. Of 8 new links, 6 came as plain text, and the 404 was recorded as `not found`.
- **Unread bundle:** a run whose read job never ran was picked up and read by the next run. That next run had reopened the same links, which only happens after a failed read.
- **Owner pushing mid-run:** the owner pushed new links while the bot was saving, and the rebase went through.
- **JavaScript-only item added:** every saved page was re-read. The 12 plain-text pages came out `2 of 3` and were copied into `check/`. New pages were switched to the browser after 3 checks. The *reopen missing* run then filled all 12, and `check/` emptied itself.
- **Failures:**
  - A wrong password, or a plan out of data, stops the run up front with a clear message, including the encrypted `CONNECT … 407` case.
  - An unreachable proxy stops it up front too, so no link loses a try.
  - Mid-run, 6 errors in a row (not blocks) stop the run.
  - A missing secret, invalid JSON in `fields.json`, a field named like a built-in column, and no links file each stop with a plain message.
  - Errors count toward 3 tries, and *retry failed* reopens those links.
- **Scale:** with 130,000 links, reading the links takes 0.2 s, saving 125,000 results (85 MB with 5 items of 120 characters) 1.2 s, loading them 0.8 s and planning 1.2 s.
- **Split:** the split into 3 files read back identical and merged back into one.
- **Privacy:** none of the 446 lines of logs, summaries and outputs contained a link, page text, collected value, username or password.
  - Every hostname in the links file is also hidden as "[the site]", because some network errors name the host without a full link.
  - A final clean run (samples, then `fields.json`, then the rest: 29 ok and 1 not found, 100% of items) was clean as well.
- **Lint:** `actionlint` (with shellcheck) passes on `10.yml`.

**Not tested:** real GitHub Actions (triggers, artifacts, `gh` calls, dispatch), real Decodo, and real Cloudflare from GitHub's Linux machines. The first sample run on GitHub is the real test.
