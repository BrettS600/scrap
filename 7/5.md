1. **Never look at the owner's links, the pages they open, or the collected data.**
   - The links live in `~/scrap-private/links.csv` on the owner's Mac, plus a spreadsheet used by `4.py`.
   - Don't ask for them, don't accept them as uploads, and don't try to work out which site it is.
   - The scripts print only row numbers and counts.
   - *Exception:* if the owner tells you that **you** are the second chat, the one allowed to see the pages, see "If you are the second chat" below.
2. **Never handle the proxy password.** It lives only on the Mac, in `~/decodo-password.txt`.
3. **Every file added to the scrap repo is named with a number** (`1.md`, `2.txt`, `3.py`…, with notes in `7/`).
4. **Don't open the owner's other GitHub repositories.** Only `BrettS600/scrap` (public since 31 Oct). **Never open `BrettS600/results-links`**, even though it's public. It holds the links, samples and results, and the builder chat promised never to go in.
5. **The owner runs the scripts on their own Mac** (VS Code, Google Chrome) and presses Run. An AI can't open the sites itself, and watching the screen would show the address bar.
6. **No phone alerts.** Build only what's asked. Keep answers short and direct, with plain recommendations, not lots of questions.

## The conversation, in order

**1. Gemini's checklist vs. Scrapling.** The owner shared Gemini's answer on what scraping behind Cloudflare needs (stealth browser, TLS and header matching, challenge solvers, residential proxies, keeping the `cf_clearance` cookie, fingerprinting, human behaviour, DNS and WebRTC leaks), and asked which of these Scrapling has.

*Answer:*
- **Scrapling has:**
  - a stealth browser (`StealthyFetcher`/`StealthySession`, Patchright-based; real Chrome via `real_chrome=True`);
  - Cloudflare Turnstile and "Just a moment" solving (`solve_cloudflare=True`, timeout ≥60 s);
  - TLS impersonation and real headers;
  - sessions that keep cookies, with `save_state`/`load_state`;
  - canvas noise, WebRTC and DNS-leak blocking, time zone and locale settings;
  - proxy rotation (bring your own proxies);
  - spiders with rate limiting and AutoThrottle;
  - CSS, XPath and adaptive selectors;
  - recording of a page's background requests.
- **Scrapling lacks:**
  - the residential proxies themselves;
  - human-like mouse and typing;
  - random timing;
  - documented audio, WebGL or font spoofing;
  - automatic hand-off of the Cloudflare pass to the plain HTTP fetcher.
- Google's page cache, one of Gemini's alternatives, no longer exists (shut down in 2024).

**2. "So it offers everything except a residential proxy?"** Mostly yes. The owner's home internet already is a residential IP, so start there at low volume.

**3. "Proxies change your IP address, correct?"** Yes; the site sees the proxy's IP.
- *Rotating* means a new IP often; *sticky* means the same IP for a set time.
- Use sticky for Cloudflare, because the pass is tied to the IP.

**4. "What's the best proxy, and what does it cost?"** A first look at prices. This was later revised in step 10.

**5. "How fast is 1,000?"** 1,000 a day is one every ~90 s. At about 1 MB per page that's ~30 GB a month. Checking every 10 s from one home IP risks blocks.

**6. Repo created.** The owner asked for a new repo named `scrap`, with every file named a number and the best of Scrapling.
- Created as **private**, with files `1.md`–`5.py`.
- The watcher checks a page every ~90 s from the home IP.
- The owner said: "don't look at my other repositories." None were opened.

**7. "Can it learn how it was blocked and update itself?"** Yes, within limits. `4.py` now:
- tells apart rate limits, Cloudflare challenges, fingerprint bans, firewall blocks, IP bans and quiet blocks;
- tries the right fix for each (waiting, a visible Chrome window, a fresh session, switching browser, slowing down);
- learns the safest speed and setup for each site, and re-finds listings after small redesigns;
- never rewrites its own code.

**8. "What happens when it runs out of fixes?"** It goes quiet: it sleeps 3, 6, 12, then 24 hours between single test checks, then resumes slower. It never quits on its own. The owner said phone alerts weren't needed.

**9. Private links.** The owner shared a spreadsheet with their links highlighted black, so Claude wouldn't see them. They asked to open "the second link" in Chrome without Claude seeing the address.
- *Answer:* yes. The script reads the link from the spreadsheet on the Mac and never prints it, and the owner presses Run.
- Don't put the spreadsheet in the repo. Black highlighting only hides the text visually.
- The owner ran it and **it worked**. They meant **row 3**, so the default became row 3, and that worked too.
- The first load took ~45 s, which was Cloudflare's check.
- It reuses one Chrome window and checks every ~90 s until stopped.

**10. Proxy for ~115,000–130,000 lookups behind Cloudflare.**
- *Recommendation:* **Decodo**. In Proxyway's independent 2026 test of 13 providers, Decodo had 99.92% success and a big US pool. The $1/GB pools (DataImpulse, Evomi) had about half their IPs already flagged, which is bad for Cloudflare.
- The owner only needs **text**. So the plan is: a browser passes Cloudflare once per IP, then the pages come as plain text over the same IP with the same pass.
- Estimated total for 130,000: **~4–40 GB, ~$16–160**, if plain text works; 40–130 GB if the browser is needed. These are estimates, to be measured.
- The owner asked to be told the best option outright, without more questions; the answer was Decodo.

**11. Buying it.**

- Advice: start the **100 MB free trial** (or Pay As You Go at ~$4/GB), not the 25 GB plan at $81.25 a month that auto-renews. The owner started the trial.

**15. `8.py` built** for that.
- Everything private lives in `~/scrap-private`.
- **Sample run:** saves the first 20 pages for the second chat.
- **`fields.json`:** the second chat writes the rules for what to collect.
- **Full run:** collects those items into `results.csv`, one row per link.
- Picks up new links on the next run, or every `WATCH_MINUTES`.
- Matches each browser's clock to its proxy IP's time zone.
- Falls back to the browser when an item only appears after the page's JavaScript runs.
- Prints only row numbers and counts.
- Tested on a fake site and proxy.

**17. "All on GitHub, so it runs with my laptop off."** Adding a link should queue the opening of its page, and an opened page should queue the reading of its text. All links go in one file and all results in one file. Later, a phone barcode scan could add a link.

- The hand-over between them is the saved page, not a screenshot, because a screenshot would need OCR or an AI to read back.
